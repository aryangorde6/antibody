### Finding 1 — **REAL BUG: `antibody.py` imports Unix-only modules unconditionally; the README command fails immediately on Windows**

**Files:** [`antibody.py:19–23`](.bob/skills/recurrence-audit/scripts/antibody.py:19) · [`README.md:22`](README.md:22)

`fcntl` and `resource` are imported unconditionally at module load:
```python
import fcntl     # line 19 — Linux/macOS only
import resource  # line 23 — Linux/macOS only
```
The README "By hand" step says to run `python3 antibody.py <step>` — on Windows this dies instantly with `ModuleNotFoundError: No module named 'fcntl'` before any step executes. The CI uses `ubuntu-latest` so it never catches this.

**Confirm:** `python3 .bob/skills/recurrence-audit/scripts/antibody.py --help` on Windows.

---

### Finding 2 — **CI SILENTLY SKIPS Python 3.12 setup; the gate would fail on a standard GitHub runner**

**File:** [`.github/workflows/antibody.yml`](.github/workflows/antibody.yml)

The entire workflow has only one action: `actions/checkout@v4`. Every subsequent command calls `python3.12` directly. GitHub's `ubuntu-latest` image ships Python 3.10 and 3.11 as the default `python3`; `python3.12` is available on current images but is not guaranteed and is not the default. There is no `actions/setup-python` step, no `python-version` pin, and no `deadsnakes/action`.

If `python3.12` is not found the workflow errors out at line 37 before any gate logic runs — but the error is in a bash subshell assignment, so whether it exits cleanly or silently depends on shell behaviour. More importantly, any future runner image change could silently break this.

**Confirm:** Remove `python3.12` from `PATH` or try `python3.12 --version` on a stock Ubuntu 22.04 image.

**Files:** [`README.md:22`](README.md:22) · [`antibody.py:12`](.bob/skills/recurrence-audit/scripts/antibody.py:12) · [`antibody.py:242`](.bob/skills/recurrence-audit/scripts/antibody.py:242)

### Finding 6 — **`n_before_caught` counts only CAUGHT rows, not "existing-test-only" rows — correct, but the label "Before" is ambiguous**

**File:** [`antibody.py:2854`](.bob/skills/recurrence-audit/scripts/antibody.py:2854)

```python
n_before_caught = sum(1 for r in ledger_rows if r["status"] == "CAUGHT")
```

"Before" means "caught by the project's own pre-existing tests, before Antibody wrote new ones." This is accurate. However, the page note ([`site/sqlparse/index.html:185`](site/sqlparse/index.html:185)) says CAUGHT + NOW CAUGHT + STILL EXPOSED + NO CHANGE FOUND = 20. The denominator therefore includes 1 STILL EXPOSED and 1 NO CHANGE FOUND row — bugs where *no test exists at all*. Calling those "checkable" implies a test could have caught them, which for STILL EXPOSED is false by definition.

This is a framing issue rather than a numerical error — the numbers are internally consistent — but a judge will ask why a STILL EXPOSED bug counts toward the denominator.

**No fix needed to confirm correctness; the numbers add up.**
